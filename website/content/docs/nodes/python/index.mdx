Nodes cover the structure of an add-on. When a step is quicker to write as code, these nodes put Python into the flow: a line typed on the node, or a script from a text block or a `.py` file. They're in **Add › Python**.

![A Python Expression with the inputs obj and factor, and a Python Statement hiding the object, in an operator](/screenshots/python-expression.webp)

| Node | |
| --- | --- |
| [**Python Expression**](/docs/nodes/python/blender-api#python-expression) | A value from one line of Python. Names the line doesn't define become inputs |
| [**Python Statement**](/docs/nodes/python/blender-api#python-statement) | Runs a line of Python in a flow |
| [**Get Attribute**](/docs/nodes/python/blender-api#get-attribute-and-set-attribute) | Reads an attribute whose name is only known when the add-on runs |
| [**Set Attribute**](/docs/nodes/python/blender-api#get-attribute-and-set-attribute) | Sets an attribute by its name |
| [**Inline Script**](/docs/nodes/python/script-nodes#inline-script) | Runs the code of a text block or a file where it is in the flow |
| [**Script Function**](/docs/nodes/python/script-nodes#script-function) | Calls a function of one of the add-on's scripts |

Which one to use:

- One line: **Python Expression** for a value, **Python Statement** for an action.
- A few lines in one place, like the body of an operator: **Inline Script**.
- Code you want to reuse, or classes and handlers of your own: a script in the **Files** list, called with **Script Function**. See [Scripts](/docs/concepts/scripts).
