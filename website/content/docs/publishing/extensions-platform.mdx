Add-ons on [extensions.blender.org](https://extensions.blender.org) are reviewed against the [moderation guidelines](https://developer.blender.org/docs/features/extensions/moderation/guidelines/). The code Scripting Nodes writes follows them; what you build with the nodes can still break them.

## Checking your add-on

**Addon › Extensions Platform** in the sidebar lists what reviewers would ask you to change. It's checked when you export, or with **Check**. The magnifier next to an entry jumps to the node that causes it.

| Entry | What to do |
| --- | --- |
| **Uses all of bpy.data.…** | A Blender Data node starting at the blend file. Start at the Context instead (`scene.objects`, `selected_objects`): the add-on should work on what the user is working on. |
| **Expects a data-block named …** | A key picked by name ("Cube"). The user's file may not have it: let the user pick the data, or use the active one. |
| **Writes into the add-on's folder** | A file path made from Add-on Info's Folder. That folder is replaced when the add-on updates: write to `bpy.utils.extension_path_user(__package__, create=True)`. |
| **Changes the sys module** | Python code changing `sys.path` or `sys.modules`. Not allowed. |
| **Reads or writes files / Connects to the internet / Uses the clipboard** | Python code or a script doing it without the permission. Turn it on under **Metadata › Permissions**. Network access also has to check `bpy.app.online_access` first. |
| **Set an author / Write a tagline** | Fill in **Metadata**: the platform shows them. |

Errors (red) are rejected, the other entries are what reviewers usually point out.
