Everything in a Blender file can be reached by following a path: the active object, its modifiers, the width of its Bevel modifier. The **Blender Data** node follows one such path and outputs what it finds.

![Blender Data nodes reading the active object's Bevel width and its mesh's vertex count](/screenshots/blend-data.png)

## The Blender Data node

Add it from **Add › Data › Blend Data**. The menu has ready-made entries for common starting points (Active Object, Selected Objects, Scene, View Layer, All Objects, Blend File, ...), which add the node already set up.

A path has a **start** and the steps after it:

- **Context**: what's current where your code runs, e.g. `active_object`, `scene`, `selected_objects`.
- **Blend File**: everything in the file, e.g. `objects`, `materials`, `scenes`.
- **Input**: the data connected to the node's **Data** input. Use it to continue from another node, e.g. the `modifiers` of an object.

Type in the path field to search: it only offers what exists at that point, so after `active_object.` you get the properties of an object. The header shows where the path ends, e.g. **Modifiers[] › Width**.

## Typed outputs

The output has the type of what the path ends at: **Width** is a Float, **Use Simplify** a Boolean, **Active Object** an Object. Connected nodes know the type too, so a second Blender Data node set to start at its Input only offers the properties of an Object.

Some paths can hold different types: `active_object.data` is a mesh for a mesh object but a camera for a camera. Pick the type with the arrow next to the output (**Data ⌄ Mesh**) to continue with mesh properties like `vertices`.

Lists (collections, drawn with a square socket) work with the **Collection** nodes (Length, Get Item, For Each, ...).

## Items of a list

`[]` in a path picks one item of a list. Each `[]` adds an input, and the icon next to it chooses how the item is picked:

- **Index**: by position, `0` is the first, `-1` the last.
- **Name**: by name, e.g. the modifier called "Bevel".
- **Active**: the list's active item, where the list has one (e.g. `material_slots`).

## Exploring the open file

The **Blend Data** tab in the node editor's sidebar shows the data of the open file, one level at a time: the real objects, modifiers and values, not just what could be there.

![The data explorer at the active object's Bevel modifier](/screenshots/blend-data-explorer.png)

- Start at **Context** (the active object, the scene, ...) or **Blend File** (all objects, materials, ...) and click entries to go into them. The top shows where you are as a path, the same way a node writes it. **Back** goes up one step, the home button back to the start.
- Entries with an arrow can be opened (objects, modifiers, lists); below them are the values with what they are right now. Empty entries and read-only values are hidden until you tick **Show Empty and Internal**.
- **+** adds a Blender Data node for an entry.
- With a Blender Data node selected (or a property node in Blender mode), **Go to Its Path** shows the data at the end of its path, and **Use This Path** sets its path to where you are. Browsing never changes a node by itself.

When the data isn't there right now (no active object, for example), the explorer lists what the type has instead, without values.

## Generated code

The node becomes the path itself, written with the `context` the surrounding function gets (or `bpy.context` where there is none):

```python
def execute(self, context):
    sn_print(str(context.active_object.modifiers['Bevel'].width))
    sn_print(str(len(context.active_object.data.vertices)))
```

To change a value instead of reading it, use **Set Property** with a path, see [Data paths](/docs/blend-data/data-paths).
