Nodes that work with one property (**Get Property**, **Set Property** and the fields **Checkbox**, **Number Field**, **Text Field**, **Vector Field**, **Enum Menu**, **Pointer Field**) can use a Blender property instead of one of your add-on's. Switch the picker next to the property to **Blender** and enter the path of the property.

![A panel drawing Use Simplify, End Frame and a Bevel modifier's width by their paths](/screenshots/blend-data-paths.png)

The path works like the one of the [Blender Data](/docs/blend-data/accessing-data) node, but must end at a property. The fields only take properties they can draw: a Checkbox a boolean, a Number Field a number; the browser says so when the path ends somewhere else. Set Property gets a **Value** input of the property's type.

The browser's search finds data by name: `parti` lists the particle systems and the properties named after particles, not everything inside them. Add words to reach further in (`particle density`), or type a path: `active_object.active_material.` lists everything on the material.

## Copying paths from Blender

You don't have to know the path. Right-click any field in Blender and choose **Copy Data Path for Scripting Nodes**, then use the paste button next to the path (or **Add › Data › Blender Data › Paste Data Path** for a new node).

Pasting turns the path into steps and inputs:

- `bpy.data.objects["Cube"].modifiers["Bevel"].width` starts at **Blend File**, and each `[...]` becomes an input with its name (`Cube`, `Bevel`) or index.
- Blender copies the active scene as `bpy.data.scenes["Scene"]`. When that's the scene you're in, it's pasted as `context.scene`, so the add-on works in other files and scenes too.
- Settings without a full path (tool settings, editor settings) are pasted to start at the node's **Input**; connect the data they belong to.

## Paths as text

You can also type a path. Segments are separated by dots and `[]` marks where an item of a list is picked, e.g. `objects[].modifiers[].width` with an input for each `[]`. A path that doesn't exist shows what's wrong under the field (*Object has no 'widht'*), and the node shows an error until it's fixed.

<Callout>Hard-coded names like `objects["Cube"]` only work in files that have that object. For add-ons you share, start at the context (the active object, the scene) where you can.</Callout>
